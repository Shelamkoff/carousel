# @shelamkoff/carousel

[![версия npm](https://img.shields.io/npm/v/%40shelamkoff%2Fcarousel)](https://www.npmjs.com/package/@shelamkoff/carousel)
[![Онлайн-демо](https://img.shields.io/badge/demo-live-4357b4)](https://shelamkoff.github.io/carousel/)
[![Лицензия MIT](https://img.shields.io/badge/license-MIT-2ea44f)](./LICENSE)

Независимая от UI-фреймворков карусель и слайдер с позиционной моделью, адаптивной раскладкой, зацикливанием, отменяемыми переходами, типизированными событиями, сенсорными жестами, доступностью и подключаемыми плагинами. Поставляется как ESM-пакет для современных браузеров.

[Онлайн-демо](https://shelamkoff.github.io/carousel/) · [Демо API слайдов](https://shelamkoff.github.io/carousel/demo-assets/api.html) · [npm](https://www.npmjs.com/package/@shelamkoff/carousel) · [English README](./README.md)

## Возможности

- Адаптивная раскладка с одним или несколькими слайдами и фиксированным либо автоматическим шагом.
- Зацикливание, 14 встроенных переходов, пользовательские эффекты, клавиатура, сенсорные жесты и перетаскивание мышью.
- Плагины стрелок, точек, миниатюр, автопоказа, ленивой загрузки, жестов и параллакса.
- Независимый от фреймворков жизненный цикл, типизированные события и объявления TypeScript.
- Точечные обновления, перестановка и замена коллекции по ключам с сохранением неизменившегося содержимого.
- Пользовательская числовая геометрия и совместимые эффекты содержимого на общей шкале отрисовки.

## Установка

```bash
npm install @shelamkoff/carousel @shelamkoff/event-bus
```

Один раз подключите обязательные стили:

```js
import '@shelamkoff/carousel/styles.css'
```

Экспорт `carouselStylesUrl` позволяет приложению самостоятельно создать элемент `<link>`.

## Быстрый старт

```html
<div id="gallery"></div>
```

```js
import {
  Carousel,
  createArrows,
  createDots,
  createKeyboard,
  createSwipe,
} from '@shelamkoff/carousel'
import '@shelamkoff/carousel/styles.css'

const carousel = new Carousel('#gallery', [
  {
    content: () => Object.assign(document.createElement('img'), {
      src: '/photos/forest.jpg',
      alt: 'Лес',
    }),
    thumb: '/photos/forest-thumb.jpg',
  },
  { content: '<p>Доверенная разметка приложения</p>' },
], {
  loop: true,
  gap: 16,
  plugins: [
    createArrows(),
    createDots(),
    createKeyboard(),
    createSwipe({ mouse: true }),
  ],
})

const unsubscribe = carousel.on('slide:change', ({ index, slide }) => {
  console.log(index, slide.meta)
})

carousel.next()

// При освобождении ресурсов:
unsubscribe()
carousel.destroy()
```

Контейнером может быть `HTMLElement` или CSS-селектор. Если селектор не находит элемент, конструктор выбрасывает исключение.

## Данные слайда

```ts
interface SlideData {
  id?: string | number
  content: string | HTMLElement | (() => HTMLElement)
  thumb?: string
  lazy?: boolean
  meta?: Record<string, unknown>
}
```

- Функция рендеринга — предпочтительный вариант для динамических или недоверенных данных.
- Переданный `HTMLElement` **клонируется** через `cloneNode(true)`. Обработчики, зарегистрированные на оригинальном элементе через `addEventListener`, не копируются. Для интерактивного содержимого используйте функцию рендеринга.
- Строка интерпретируется как HTML и считается доверенной конфигурацией разработчика.
- `thumb` использует плагин миниатюр, `lazy` — ленивая загрузка, а `meta` остаётся метаданными приложения.
- `id` — необязательный стабильный идентификатор для обновлений коллекции новыми объектами. Допустима непустая строка или конечное число, уникальное в коллекции; число `1` и строка `'1'` различаются. Без `id` сопоставление использует ссылку на объект слайда. См. [изменение слайдов](#изменение-слайдов-без-повторного-монтирования).

## Конфигурация

| Поле | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `slidesPerView` | `number` | `1` | Количество видимых слайдов. Поддерживаются положительные дробные значения, в том числе `1.15` и `2.25`. |
| `slidesPerScroll` | `number \| 'auto'` | `1` | Шаг навигации. `'auto'` использует текущее количество видимых слайдов. |
| `gap` | `number` | `0` | Расстояние между слайдами в CSS-пикселях. |
| `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` | Ось раскладки, навигации, клавиатуры, свайпа и параллакса. |
| `layout` | `CarouselLayout` | `'standard'` | `'standard'`, `'expand'` или объект пользовательской числовой геометрии. |
| `expandVisible` | `number` | `2.5` | Число эквивалентов узких карточек в расширяющейся раскладке; допускаются дробные значения. |
| `expandRatio` | `number` | `2.5` | Отношение размеров активной и узкой карточки, не меньше 1. |
| `expandPeek` | `number` | `32` | Ведущий отступ в пикселях, не более четверти видимой области. |
| `viewportHeight` | `number` | CSS `400px` | Положительная высота вертикальной видимой области в CSS-пикселях. Без опции применяется `--carousel-vertical-height`. |
| `transition` | `CarouselTransition` | `'slide'` | Имя встроенного эффекта или объект пользовательского перехода. См. раздел ниже. |
| `transitionDuration` | `number` | `400` | Длительность перехода в миллисекундах. |
| `loop` | `boolean` | `false` | Циклическая навигация с позиционированием исходных слайдов. Только для коротких циклов создаются неинтерактивные визуальные копии. |
| `startIndex` | `number` | `0` | Начальный логический индекс. Используется только при создании. |
| `ariaLabel` | `string` | `'Carousel'` | Доступное имя области карусели для вспомогательных технологий. |
| `breakpoints` | `Record<number, Partial<CarouselResponsiveOptions>>` | нет | Переопределения, действующие начиная с указанной ширины области просмотра. |
| `plugins` | `CarouselPlugin[]` | `[]` | Плагины, устанавливаемые при создании. |

Настройки контрольной точки переопределяют базовые. При смене контрольной точки, изменении коллекции и `update(options)` сохраняется DOM неизменившихся слайдов. **Миграция:** `update()` больше не вызывает функции рендеринга повторно. Для явного сброса содержимого используйте `refresh(index)` для одного слайда или `refresh()` для всей коллекции. При `prefers-reduced-motion: reduce` анимации навигации отключаются.

```js
const carousel = new Carousel('#gallery', slides, {
  slidesPerView: 1,
  slidesPerScroll: 'auto',
  breakpoints: {
    640: { slidesPerView: 2, gap: 12 },
    1024: { slidesPerView: 4, gap: 20 },
  },
})
```

### Дробные значения и вертикальная галерея

`slidesPerView` не округляется: `1.15` и `2.25` показывают часть следующего слайда с учётом указанного `gap`. Это работает в обычной и зацикленной раскладке. `slidesPerScroll: 'auto'` использует целую часть видимого количества, но не меньше одного; явное положительное целое число задаёт шаг независимо.

```js
const gallery = new Carousel('#gallery', slides, {
  orientation: 'vertical',
  viewportHeight: 420,
  slidesPerView: 1.15,
  gap: 16,
  loop: true,
  plugins: [createArrows(), createKeyboard(), createSwipe({ mouse: true })],
})
gallery.update({ slidesPerView: 2.25 })
```

В вертикальном режиме используются клавиши Up/Down, вертикальный свайп и стрелки сверху/снизу. Сенсорная прокрутка по поперечной оси и масштабирование двумя пальцами сохраняются. Высоту можно задать через `viewportHeight` либо, без этой опции, через `--carousel-vertical-height: clamp(280px, 60vh, 520px)` на контейнере. CSS-значение по умолчанию — `400px`. Горизонтальная галерея по-прежнему получает высоту от содержимого. Направление и высота изменяются через `update()` и breakpoints; пороги breakpoints по-прежнему определяются шириной окна. Все пресеты переходов работают с обеими ориентациями. Рисунок масок, например `stairs-horizontal`, сохраняет собственное направление.

[Открыть вертикальную галерею с `1.15` слайда](https://shelamkoff.github.io/carousel/?orientation=vertical&slidesPerView=1.15#gallery-example).

### Расширяющиеся карточки

`layout: 'expand'` создаёт акцентную карточку с узкими соседними превью, как в редакционной галерее. Это **тип раскладки**, а не декоративная маска: ширины карточек и позиция текста меняются по общему времени анимации. Каждая карточка получает непрерывную CSS-переменную `--carousel-expand-focus` от 0 до 1. Готовые стили управляют заголовком и подписью при использовании классов `carousel__expand-card`, `carousel__expand-image`, `carousel__expand-caption`, `carousel__expand-title`, `carousel__expand-meta`. Собственная разметка также может использовать эту переменную.

```js
const carousel = new Carousel('#stories', storySlides, {
  layout: 'expand',
  slidesPerView: 1,
  expandVisible: 2.45,
  expandRatio: 2.6,
  expandPeek: 28,
  gap: 16,
  loop: true,
  transitionDuration: 650,
  plugins: [
    createArrows(), createSwipe({ mouse: true }), createKeyboard(),
    createAutoplay({ interval: 5500 }),
    createControls({ progress: 'bar', playPause: true, counter: true }),
  ],
})
```

В этом режиме активен ровно один логический слайд (`slidesPerView: 1`), а `expandVisible` определяет долю видимых узких превью и допускает дробные значения. `expandRatio` и `expandVisible` должны быть не меньше 1, `expandPeek` — неотрицательным. Переход `fade` несовместим с этой раскладкой; `slide` и эффекты закрытия области доступны. Поддерживаются горизонтальное и вертикальное направления, breakpoints, обновления, короткие циклы, свайпы и режим уменьшения движения. Высота горизонтальной карточки задаётся через `--carousel-expand-height`, вертикальная высота — через `viewportHeight`. Темизация доступна через `--carousel-expand-radius`, `--carousel-expand-inset`, `--carousel-expand-badge-bg`, `--carousel-expand-card-bg` и `--carousel-expand-scrim`.

[Открыть демо расширяющихся карточек](https://shelamkoff.github.io/carousel/#expand-example).

### Play/Pause, время показа и счётчик

Плагин `createControls()` добавляет необязательные элементы управления. Его можно подключить до или после `createAutoplay()`: кнопка воспроизведения и прогресс показываются только при установленном автопоказе. Счётчик работает и без автопоказа.

```js
const controls = createControls({
  playPause: true,
  progress: 'circle', // 'circle', 'bar' или false
  counter: true,
  position: 'below', // 'below' или 'overlay'
  labels: { play: 'Начать автопоказ', pause: 'Приостановить автопоказ' },
})
const gallery = new Carousel('#gallery', slides, {
  slidesPerView: 2.25,
  gap: 16,
  loop: true,
  plugins: [
    createArrows(), createSwipe({ mouse: true }),
    createAutoplay({ interval: 4500, pauseOnInteraction: false }),
    controls,
  ],
})
controls.update({ progress: 'bar', counter: false })
```

Видимость каждого элемента независима и меняется без пересоздания карусели. Прогресс использует те же часы, что и автопереключение: пауза замораживает его, Play продолжает оставшееся время, а после перехода новый слайд получает полный интервал показа. Наведение, клавиатурный фокус и скрытая вкладка приостанавливают автопоказ. Явное нажатие Play разрешает продолжение, пока сама кнопка находится под курсором или в фокусе; перенос фокуса на другой элемент снова приостанавливает показ. `pauseOnInteraction` по умолчанию равен `true`; `false` разрешает продолжение после ручной навигации. Подробности API и локализации: [Autoplay](src/plugins/autoplay/README.ru.md), [Controls](src/plugins/controls/README.ru.md).

Счётчик показывает выбранный логический слайд и количество исходных слайдов: например, `1 / 7`, а для пустой галереи — `0 / 0`. Визуальные копии не учитываются. В обычной галерее с несколькими видимыми слайдами конечное значение может быть `6 / 7`: слайд 7 уже виден рядом со слайдом 6. Это номер слайда; количество страниц показывают точки пагинации. `formatCounter(current, total)` позволяет безопасно изменить текст счётчика.

## Переходы

| Значение | Эффект |
| --- | --- |
| `'slide'` | Перемещение трека к следующей позиции. |
| `'fade'` | Плавная смена прозрачности при одном видимом слайде; при нескольких используется перемещение трека. |
| `'stairs'` | Вертикальные панели закрывают область карусели и уходят каскадом. |
| `'stairs-horizontal'` | Восемь горизонтальных полос движутся попеременно слева направо и справа налево. При переходе назад порядок запуска полос меняется на обратный. |
| `'pixel'` | Сетка плиток закрывает и раскрывает область карусели в детерминированном порядке. |
| `'curtain'` | Две вертикальные половины смыкаются и расходятся по горизонтали. |
| `'diamond-wipe'` | Ромб расширяется из центра до полного перекрытия и затем сужается. |
| `'directional-wipe'` | Диагональная граница проходит через область карусели; переход назад зеркалит направление. |
| `'clock-wipe'` | Сектор проходит полный оборот вокруг центра; переход назад меняет направление вращения. |
| `'aperture-wipe'` | Вращающееся шестиугольное отверстие закрывается и открывается как диафрагма камеры. |
| `'polka-dots'` | Волна растущих кругов расходится от угла; сетка подстраивается под пропорции области. |
| `'grid-flip'` | 32 декоративные плитки поворачиваются последовательной диагональной волной. |
| `'doorway'` | Две декоративные створки закрываются и открываются с перспективой. |
| `'water-drop'` | Круговая заливка с концентрическими волнами закрывает и раскрывает слайд. |

Эффекты раскрытия работают на всей видимой области, включая loop и несколько одновременно видимых слайдов. `transitionDuration` задаёт общее время закрытия и раскрытия. Целевая позиция отображается, когда панели полностью закрывают карусель. Панели декоративные: они не клонируют содержимое слайдов, не меняют значения полей форм и экземпляры пользовательских элементов. Все эффекты учитывают настройку уменьшения движения.

Восемь дополнительных пресетов — реализации соответствующих визуальных приёмов средствами CSS. Grid flip и Doorway анимируют панели в цветах темы, Water drop — круговую заливку и волны. Они не искажают текстуру фотографии и не требуют WebGL, снимков через canvas, внешних изображений или новых зависимостей. Эффекты работают с формами, видео и произвольным HTML. Каждый использует не более 64 декоративных элементов, измеряет геометрию только при создании и следует общим часам анимации и очистке карусели.

[Посмотреть все эффекты в живом демо](https://shelamkoff.github.io/carousel/#transitions-example). Нажмите на пресет для воспроизведения, измените длительность и цвет панелей или скопируйте **Link to this effect**, чтобы поделиться выбранным переходом.

```js
const carousel = new Carousel('#gallery', slides, {
  transition: 'pixel',
  transitionDuration: 800,
})

carousel.update({ transition: 'curtain' })
```

Цвет панелей задаётся CSS-переменной на контейнере карусели:

```css
#gallery {
  --carousel-transition-color: #17181b;
  --carousel-transition-highlight: rgba(255, 255, 255, 0.18);
}
```

### Пользовательские переходы

Передайте объект `CarouselTransitionDefinition` в `transition`: регистрация в глобальном реестре и изменения ядра не нужны. Каждая навигация вызывает `create()` и получает отдельный renderer. Один объект можно использовать в нескольких каруселях, в `update()` и в breakpoints.

```js
const iris = {
  name: 'iris',
  create({ container, direction }) {
    const panel = container.ownerDocument.createElement('div')
    Object.assign(panel.style, {
      position: 'absolute', inset: '0',
      background: 'var(--carousel-transition-color, #17181b)',
    })
    container.appendChild(panel)
    return {
      render(progress) {
        const cover = progress < 0.5 ? progress * 2 : (1 - progress) * 2
        const eased = cover * cover * (3 - 2 * cover)
        panel.style.clipPath = `circle(${eased * 75}% at 50% 50%)`
      },
    }
  },
}

carousel.update({ transition: iris, transitionDuration: 800 })
carousel.on('transition:error', ({ name, error }) => console.error(name, error))
```

`container` — декоративный слой с обрезкой по viewport, `inert` и автоматической очисткой. Создавайте элементы через его `ownerDocument`. `direction` равен `1` при движении вперёд и `-1` при движении назад, включая переход через границу loop. Симметричный iris не использует направление. Изменяйте только свой слой, не переносите и не клонируйте живые слайды. Элементы слоя наследуют тему карусели.

`create()` и `render()` синхронные. Прогресс изменяется от `0` до `1`: в начале и конце слой должен быть прозрачным, а при `0.5` — полностью закрывать viewport. Карусель обязательно отрисовывает эту точную границу перед сменой слайдов, даже если кадр задержался. Ядро управляет временем, длительностью, уменьшением движения, прерыванием и событиями. При уменьшении движения или нулевой длительности фабрика не вызывается: навигация завершается сразу. При изменении ширины viewport карусель устанавливает целевой слайд и удаляет эффект.

Необязательный `destroy()` освобождает ресурсы вне слоя: наблюдатели, сторонние экземпляры и т. п. Сам слой удаляется автоматически. Очистка выполняется при завершении, отмене, ошибке и даже если фабрика синхронно вызвала `update()` или `destroy()` карусели до возврата renderer. Если фабрика выбрасывает исключение до возврата `destroy()`, созданные внешние ресурсы она должна освободить сама. Ошибки приходят в `transition:error`; ошибка создания или отрисовки немедленно завершает актуальный переход к целевому слайду. Если callback уже обновил или уничтожил карусель, устаревший переход не завершается. Объекты переходов и их функции — доверенный код приложения, как фабрики слайдов и плагины.

## Пользовательская геометрия и эффекты содержимого

Три точки расширения можно сочетать: `layout` рассчитывает геометрию слайдов, `createSlideEffect()` анимирует их содержимое, а `transition` рисует декоративное перекрытие при навигации. Они используют позицию и время ядра; разбирать CSS-transform или запускать отдельный цикл `requestAnimationFrame` не требуется.

### Контракт числовой геометрии

```js
const compactLayout = {
  name: 'compact',
  render({ slides }) {
    return slides.map(slide => ({
      offset: slide.offset * 0.9,
      size: slide.size * 0.85,
      progress: slide.progress,
    }))
  },
}

carousel.update({ layout: compactLayout, slidesPerView: 1.6, transition: 'slide' })
```

`CarouselLayoutDefinition.render(context)` — синхронный метод. Его замороженный аргумент содержит `position`, `step`, `viewportSize`, `gap`, `count`, `loop`, `orientation` и упорядоченный массив `slides`. Каждая визуальная позиция содержит `index`, `copy`, `isCopy`, `offset`, `size` и `progress`; `copy: 0` обозначает оригинал. В коротких циклах возможны неинтерактивные визуальные копии одного логического слайда. Callback получает числа и флаги без DOM-элементов.

Верните по одной записи `{ offset, size, progress? }` для **каждой входной позиции в том же порядке**, включая копии. `offset` — смещение от начального края viewport, `size` — размер по основной оси, оба в CSS-пикселях. Значения должны быть конечными, `size` — неотрицательным. Если `progress` пропущен, сохраняется каноническое расстояние от фокуса в шагах слайдов со знаком. Ядро применяет геометрию по текущей горизонтальной или вертикальной оси.

Контракт меняет визуальную геометрию. Логическую навигацию, расстояния свайпа, границы конечной ленты и набор циклических позиций по-прежнему задают `slidesPerView`, `gap` и `slidesPerScroll`. Выбирайте эти параметры с учётом требуемой видимой области. Отдельная модель навигации при этом не создаётся. Объект поддерживается в конструкторе, `update()` и контрольных точках; `fade` требует `layout: 'standard'`.

Некорректный результат или исключение вызывает `layout:error` и включает стандартную геометрию до следующего перестроения. Весь результат проверяется до применения. Используйте callback как чистое вычисление: без DOM-измерений, асинхронной работы и изменения элементов.

### Эффекты содержимого слайдов

```js
import { createSlideEffect, createFocusEffect } from '@shelamkoff/carousel'

const captionEffect = createSlideEffect({
  name: 'caption',
  create({ setStyle }) {
    return {
      render(frame) {
        for (const slide of frame.slides) {
          const caption = slide.element.querySelector('.caption')
          const distance = frame.reducedMotion ? 0 : (1 - slide.focus) * 24
          setStyle(caption, 'translate', `0 ${distance}px`)
          setStyle(caption, 'opacity', String(0.65 + slide.focus * 0.35))
        }
      },
    }
  },
})

carousel.use(captionEffect)
const focusEffect = createFocusEffect({
  selector: '.card', scale: 0.92, opacity: 0.7, offset: 12,
})
carousel.use(focusEffect)

// Удаление эффекта восстанавливает принадлежащие ему inline-свойства.
carousel.unuse(captionEffect.name) // имя: 'effect:caption'
```

Эффект — обычный удаляемый плагин. `create()` получает `root`, `viewport` и управляемый метод `setStyle(element, property, value)`. Верните синхронный `render(frame)` и необязательный `destroy()`. Отрисовка выполняется сразу и при обновлениях ядра: навигации, перетаскивании, изменении размера, ленивом рендеринге и мутациях коллекции. В состоянии покоя отдельного опроса нет.

Передавайте в `setStyle` имена CSS-свойств: `'opacity'`, `'translate'`, `'--caption-focus'`. Элемент `null` игнорируется; значение `null` освобождает свойство. Обычные CSS-свойства применяются к принадлежащим карусели потомкам содержимого. На элементах позиционирования — root, viewport, track и обёртках слайдов — разрешены только CSS-переменные. Вложенные карусели и посторонние элементы страницы находятся вне области эффекта. Управляемые стили восстанавливаются при перестроении, удалении и ошибке; учитываются остальные активные эффекты и более новые записи приложения. Освобождайте свойства элементов, которые эффект перестал использовать.

`createFocusEffect()` — готовый пример этого контракта: неактивный `scale` по умолчанию равен `0.9`, `opacity` — `0.6`, смещение поперёк основной оси `offset` — `0`. Scale и opacity должны быть в диапазоне `0…1`. Без `selector` обрабатываются непосредственные дочерние элементы слайда. Необязательный `name` позволяет подключить несколько независимо удаляемых эффектов. Уменьшение движения отключает масштабирование и смещение; собственные эффекты также должны учитывать `frame.reducedMotion`.

Создание, отрисовка и очистка эффекта синхронные. Ошибка создания или отрисовки вызывает `effect:error`, останавливает renderer этого эффекта и восстанавливает его стили. Для повторного запуска удалите и подключите плагин заново. В `destroy()` освобождайте внешние наблюдатели, обработчики и другие созданные ресурсы; фабрика, выбрасывающая исключение до возврата `destroy()`, должна освободить уже выделенные ресурсы сама.

### Снимки состояния отрисовки

`carousel.getRenderState()` возвращает замороженный снимок `CarouselRenderState`, а после уничтожения — `null`. Подписка на `render` получает обновления. Снимок описывает последний кадр ядра и содержит актуальные ссылки на элементы без чтения их bounding rectangles:

| Поле | Значение |
| --- | --- |
| `position`, `step`, `viewportSize`, `orientation` | Каноническая позиция, шаг навигации, размер viewport по основной оси и ориентация. |
| `index`, `selectedIndex`, `fromIndex` | Текущий логический индекс позиции, выбранная цель и начало перехода. |
| `phase`, `direction`, `transitionProgress` | `'idle'`, `'drag'` или `'animation'`; направление `-1`, `0` или `1`; линейный прогресс `0…1` либо `null` вне анимации. |
| `revision`, `reducedMotion` | Ревизия структуры отрисовки и текущая настройка уменьшения движения. |
| `slides` | Упорядоченные визуальные позиции, включая неинтерактивные копии. Поля: `element`, `index`, `copy`, `isCopy`, `offset`, `size`, `progress`, `focus`, `visible`. |

`progress` — расстояние от фокуса со знаком; `focus = max(0, 1 - abs(progress))`. `visible` — доля размера позиции, пересекающая viewport, без оценки перекрытия другими элементами или реально нарисованных пикселей. При подключении поведения учитывайте `isCopy`: копии декоративные, а `getSlideElements()` возвращает только оригиналы. Заморозка снимков не замораживает DOM-элементы. `render:reset` уведомляет о предстоящем перестроении структуры или управляемых стилей; удаляйте тогда закешированные ссылки на потомков.

Expand и пользовательские раскладки также выставляют на обёртках слайдов `--carousel-slide-progress`, `--carousel-slide-focus` и совместимый алиас `--carousel-expand-focus` для оформления содержимого через CSS.

[Попробовать мутации по ключам, пользовательскую геометрию и переключение эффектов](https://shelamkoff.github.io/carousel/demo-assets/api.html).

## Темизация

Задавайте свойства `--carousel-*` на элементе, переданном в `new Carousel()`, на родительской обёртке темы или на `:root`. Созданная карусель наследует их. Значения по умолчанию подставляются в местах использования, поэтому тему можно объявлять до или после CSS библиотеки: `!important` и селекторы внутренней разметки не нужны.

```css
#gallery {

  --carousel-arrow-bg-hover: #344258;
  --carousel-arrow-color: #f4f7fc;

  --carousel-dot-bg-hover: #c4d7ff;
  --carousel-dot-bg-active: #9abaff;
  --carousel-thumb-border-color-active: #9abaff;
  --carousel-focus-color: #9abaff;
  --carousel-transition-color: #202733;
}

@media (max-width: 480px) {
  #gallery {

```

Изменение класса, data-атрибута или CSS-переменной контейнера сразу обновляет тему; вызывать `carousel.update()` не требуется. У каждой карусели может быть своя тема. Стили контейнера сохраняются при перестроении карусели и после destroy/remount.

[Попробуйте темы Light, Dark и Compact в живом демо](https://shelamkoff.github.io/carousel/#theming-example).

Пользовательская HTML-разметка стрелок сохраняет свои размеры; переменная размера иконки применяется только к встроенной `.carousel__arrow-icon`. Содержимое слайдов принадлежит приложению и может использовать его типографику, фоны и отступы.

Геометрию слайдов настраивайте через JavaScript: `gap`, `slidesPerView`, `slidesPerScroll` и `breakpoints`. Длительность навигации задаётся `transitionDuration`; `control-duration` относится только к элементам управления. `--carousel-gap` отражает вычисленный JS-отступ для внутренних эффектов и не предназначен для изменения раскладки. Старые неиспользуемые объявления `--carousel-transition-duration` и `--carousel-transition-timing` больше не предлагаются для настройки. Не переопределяйте позиционирование и transform трека и внешних обёрток слайдов. Все встроенные декоративные анимации учитывают уменьшение движения.

## Публичный API

| Метод | Результат | Назначение |
| --- | --- | --- |
| `use(plugin)` | `this` | Устанавливает плагин. Имена плагинов должны быть уникальны. |
| `unuse(name)` | `boolean` | Удаляет плагин с очисткой; возвращает `false`, если плагин с таким именем не установлен. |
| `getPlugin(name)` | плагин или `undefined` | Возвращает публичный объект установленного плагина. |
| `next()` / `prev()` | `void` | Перемещает карусель на текущий шаг прокрутки. |
| `goTo(index)` | `void` | Переходит к логическому индексу слайда. |
| `getIndex()` | `number` | Возвращает текущий логический индекс, в том числе в циклическом режиме. |
| `getRealIndex()` | `number` | Алиас `getIndex()`, сохранённый для интеграций. |
| `getSlide(index?)` | слайд или `null` | Возвращает слайд; без индекса — текущий. |
| `getSlides()` | `SlideData[]` | Возвращает защитную копию массива слайдов. |
| `getSlideCount()` | `number` | Число логических слайдов без декоративных копий. |
| `getSlideElement(index?)` | элемент или `null` | Исходная обёртка слайда; без индекса — текущего. |
| `getSlideElements()` | `HTMLElement[]` | Защитная копия массива исходных обёрток в порядке коллекции. |
| `getRenderState()` | снимок или `null` | Последний неизменяемый числовой кадр со ссылками на визуальные элементы. |
| `updateSlide(index, patch)` | `void` | Поверхностно объединяет переданные поля. Замена содержимого затрагивает только этот слайд; `id` фиксирован. |
| `moveSlide(from, to)` | `void` | Перемещает слайд на конечный индекс массива, сохраняя выбранный слайд по идентичности. |
| `setSlides(slides)` | `void` | Сопоставляет коллекцию по `id`, а слайды без `id` — по ссылке на объект. |
| `refresh(index?)` | `void` | Явно сбрасывает содержимое одного слайда или всей коллекции. Ленивые слайды повторно рендерятся при запросе. |
| `addSlide(slide, index?)` | `void` | Добавляет слайд и перестраивает раскладку. |
| `removeSlide(index)` | `void` | Удаляет логический слайд и корректирует текущий индекс. |
| `update(options)` | `void` | Меняет поведение и раскладку, сохраняя неизменившееся содержимое. Поля `plugins` и `startIndex` не принимаются. |
| `on(event, handler)` | функция отписки | Подписывает обработчик на событие. |
| `off(event, handler)` | `void` | Удаляет конкретный обработчик. |
| `once(event, handler)` | функция отписки | Подписывает обработчик на одно срабатывание. |
| `destroy()` | `void` | Отменяет анимации, уничтожает плагины, удаляет созданный DOM и обработчики. |

После `destroy()` экземпляр использовать нельзя. Для повторного монтирования создайте новую карусель.

### Изменение слайдов без повторного монтирования

```js
// Стабильные id нужны, когда приложение создаёт новые объекты данных.
const slides = [
  { id: 'forest', content: renderForest, meta: { title: 'Лес' } },
  { id: 'coast', content: renderCoast, meta: { title: 'Берег' } },
]
const carousel = new Carousel('#gallery', slides, { loop: true })

carousel.updateSlide(0, { meta: { title: 'Новое название' } }) // сохраняет содержимое
carousel.updateSlide(1, { content: renderNewCoast })           // заменяет только coast
carousel.moveSlide(0, 1)                                     // порядок: coast, forest
carousel.setSlides(carousel.getSlides().reverse().map(slide => ({ ...slide })))
carousel.update({ gap: 24 })                                 // сохраняет содержимое
carousel.refresh(carousel.getIndex())                        // сбрасывает выбранное
```

`renderForest`, `renderCoast` и `renderNewCoast` в примере — функции приложения, возвращающие `HTMLElement`. Для сохранённой идентичности `setSlides()` оставляет содержимое, если значение/ссылка `content` не изменились. Новая inline-функция рендеринга считается изменением содержимого, даже если возвращает такую же разметку. Патч метаданных сохраняет значения полей и обработчики; `meta` заменяется целиком, без рекурсивного объединения. Передача `content` в `updateSlide()` явно обновляет этот слайд, даже если значение/ссылка прежние. Используйте методы мутации, а не прямое изменение объектов из getters: массив копируется, объекты слайдов глубоко не клонируются.

Через `updateSlide()` изменить `id` нельзя. Для замены идентичности используйте `setSlides()`. Повторяющиеся или недопустимые id отклоняются. `updateSlide()`, `moveSlide()` и `refresh(index)` требуют существующих неотрицательных целочисленных индексов, иначе выбрасывают `RangeError`. `moveSlide()` использует конечный индекс после удаления и ничего не делает при одинаковых индексах. `addSlide()` по умолчанию добавляет в конец; переданный целочисленный индекс ограничивается диапазоном `0…count`. `removeSlide()` игнорирует неверные индексы.

Перестановка и сопоставление по возможности сохраняют выбранную идентичность. При её удалении выбирается элемент на прежнем индексе с ограничением по новому размеру коллекции и границам конечной навигации. Поддерживается `setSlides([])` с последующим добавлением новых слайдов. Мутации отменяют текущий переход, синхронно перестраивают карусель и вызывают `slides:change`; для изменений коллекции подписывайтесь на это событие, а не на навигационное `slide:change`. Сохранённые идентичности используют прежние обёртки; замена `content` и `refresh()` намеренно заменяют их потомков. При наличии браузерной поддержки атомарное перемещение DOM также сохраняет управляемое браузером состояние при перестановке.

## События

| Событие | Данные |
| --- | --- |
| `slides:change` | `{ type, previousCount, count, index }`; `type`: `'add'`, `'remove'`, `'update'`, `'move'`, `'set'` или `'refresh'`. |
| `render` | `CarouselRenderState`; общий кадр ядра для эффектов, зависящих от позиции. |
| `render:reset` | Без данных; сброс кешированных ссылок на содержимое/геометрию перед перестроением. |
| `layout:error` / `effect:error` | `{ name, error }`; ошибка пользовательской раскладки или эффекта содержимого. |
| `slide:beforeChange` | `{ fromIndex, toIndex }` |
| `slide:change` | `{ index, prevIndex, slide }` |
| `transition:start` | `{ fromIndex, toIndex }` |
| `transition:end` | `{ index }` |
| `transition:error` | `{ name, error }` |
| `resize` | `{ slidesPerView }` |
| `autoplay:start` / `autoplay:stop` | без данных |
| `autoplay:state` | `{ available, active, paused, running, interval, remaining, progress }`; при смене состояния, без события на каждом кадре. |
| `slide:lazyload` | `{ index, element }` |
| `slide:error` | `{ index, error }` |
| `destroy` | без данных |

Ошибки отрисовки и ленивой загрузки изолируются. После создания карусели они передаются через `slide:error`. Синхронные ошибки первоначального рендеринга выводятся в консоль, поскольку подписаться на событие до завершения конструктора нельзя.

## Встроенные плагины

- [Стрелки](src/plugins/arrows/README.ru.md) — кнопки перехода; на границах скрываются по умолчанию, появление при наведении включается отдельно.
- [Точки](src/plugins/dots/README.ru.md) — нажимаемая пагинация.
- [Миниатюры](src/plugins/thumbnails/README.ru.md) — нижняя или боковая навигация.
- [Клавиатура](src/plugins/keyboard/README.ru.md) — по умолчанию обрабатывает клавиши только внутри карусели.
- [Жесты](src/plugins/swipe/README.ru.md) — сенсорный ввод, указатель, сопротивление и необязательное перетаскивание мышью.
- [Автовоспроизведение](src/plugins/autoplay/README.ru.md) — интервальное переключение с паузой при наведении и взаимодействии.
- [Элементы управления](src/plugins/controls/README.ru.md) — Play/Pause, круглый или линейный прогресс времени и счётчик слайдов.
- [Ленивая загрузка](src/plugins/lazyload/README.ru.md) — загрузка изображений через `IntersectionObserver` и предварительная подгрузка.
- [Параллакс](src/plugins/parallax/README.ru.md) — визуальное смещение, зависящее от позиции.

Настройка `createArrows({ hideOnIdle: true })` задвигает стрелки к соответствующим краям, когда курсор выходит из области слайдов. При наведении или видимом клавиатурном фокусе стрелки выдвигаются. На сенсорных устройствах и устройствах со смешанным вводом кнопки остаются видимыми; настройка уменьшения движения учитывается. По умолчанию `hideOnIdle` равен `false`. [Попробовать в демо](https://shelamkoff.github.io/carousel/#hover-arrows-example).

Tab или программный фокус на контроле невидимого слайда сразу открывает этот слайд, сохраняя согласованность индекса, нативной прокрутки и отрисованной позиции. Исходные поля, значения, обработчики и Shadow DOM сохраняются. Фокус на уже видимом контроле не сдвигает текущую страницу с несколькими слайдами. Это поведение ядра, плагин клавиатуры для него не требуется.

Плагин подключается через `plugins` или `use()` и удаляется через `unuse(plugin.name)`. Удаление вызывает `destroy()`, снимает принадлежащие плагину подписки и отзывает команды мутации старого контекста: отложенные callback больше не управляют каруселью. Удалённый экземпляр можно установить снова. Один экземпляр плагина с состоянием может принадлежать только одной активной карусели; для нескольких каруселей создавайте отдельные объекты.

## Создание плагина

Плагин содержит уникальное поле `name`, метод `install(context)` и необязательный `destroy()`:

```js
export function createProgressPlugin() {
  let element = null

  return {
    name: 'progress',

    install(context) {
      element = document.createElement('output')
      element.className = 'carousel-progress'
      element.setAttribute('aria-live', 'polite')

      const render = () => {
        element.textContent = `${context.getRealIndex() + 1} / ${context.getSlideCount()}`
      }

      context.getRoot()?.append(element)
      context.on('slide:change', render)
      context.on('slides:change', render)
      context.on('resize', render)
      render()
    },

    destroy() {
      element?.remove()
      element = null
    },
  }
}
```

Замороженный контекст предоставляет подписки на события с автоматическим владением, команды навигации и изменения коллекции, состояние и вычисленные настройки только для чтения, актуальные ссылки на DOM, позиционные методы для жестов и эффектов, `getRenderState()` и `refreshLayout()`. `getPlugin(name)` возвращает уже установленный необязательный плагин либо `undefined`. Подписки контекста удаляются автоматически. Собственный DOM, глобальные обработчики, наблюдатели, таймеры, кадры анимации, объектные URL и сторонние экземпляры плагин освобождает в `destroy()`.

Если `install()` выбрасывает исключение, карусель откатывает подписки и вызывает очистку плагина. Поэтому `destroy()` должен быть безопасен и после частичной установки.

## Проверка

Установите зафиксированные зависимости командой `npm ci`, затем запустите `npm run check`: она выполняет Node-тесты, проверку публичного TypeScript API, сборку ESM-пакета и подготовку локальной зависимости демо. GitHub Actions проверяет Node 20.19, 22 и 24 и отклоняет устаревшую копию дистрибутива. Сохранённый в репозитории `dist` также поддерживает установку из Git с отключёнными lifecycle-скриптами.

Для браузерных тестов установите Chromium командой `npx playwright install chromium` и запустите `npm run test:browser`. Проверяются навигация, формы, same-origin iframe, живые примеры и очистка при уничтожении. Для существующей установки Chromium укажите путь к исполняемому файлу в `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Диагностическая страница доступна по адресу `/tests/browser/lifecycle.html` после `npm run demo`.

## Граница безопасности

Строковые `slide.content` и пользовательская HTML-разметка стрелок вставляются как HTML. Передавайте туда только доверенную разметку разработчика. Для пользовательских данных создавайте элемент через `textContent` или предварительно очищайте значение.

JavaScript и иллюстрации демо загружаются локально; внешний CDN для работы не требуется.

[Демо API слайдов](https://shelamkoff.github.io/carousel/demo-assets/api.html) показывает точечные обновления содержимого и метаданных, замену коллекции новыми объектами с прежними ключами, перестановку, явный refresh, пользовательскую геометрию и отключаемые эффекты заголовка, фокуса и параллакса. Введите текст в карточку и проверьте сохранение состояния при изменении коллекции и раскладки.

GitHub Pages публикуется workflow `.github/workflows/pages.yml` при обновлении `master` — настроенной исходной ветки Pages. Workflow проверяет и собирает проект, затем скрипт `scripts/build-pages.mjs` подготавливает только `index.html`, исполняемые JS-модули, CSS и ресурсы демо. Публикуется статический артефакт без Jekyll. `/version.json` содержит SHA опубликованного коммита. Временные каталоги сборки создаются вне репозитория.

В репозитории также действует автоматический workflow Pages из ветки. Перед публикацией подготовленного демо `scripts/wait-for-branch-pages.mjs` ждёт завершения этого workflow для того же коммита и проверяет, что `master` всё ещё указывает на эту версию. Поэтому автоматическая публикация не перезаписывает чистую сборку демо, а устаревшие версии в очереди пропускаются. Отсутствующий запуск или ошибка API останавливают публикацию с ограниченным временем ожидания. При переключении источника Pages с ветки на GitHub Actions в настройках репозитория этот этап нужно изменить вместе с настройкой.
